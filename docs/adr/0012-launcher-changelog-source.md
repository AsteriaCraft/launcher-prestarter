# ADR 0012. Звідки сайт бере changelog лаунчера: підписаний `release-notes.json`, запасний розбір опису релізу

- Статус: запропоновано (етап Design, 2026-10-02); додати `release-notes.json` у релізи рантайму - відкрите питання
  власнику з рішенням «так» за замовчуванням
- Пов'язані: [0009](0009-ci-matrix-release-assets-and-manifest.md), [0011](0011-site-download-experience.md)

## Контекст

- Сайт показує кожну версію лаунчера з датою і пунктами «Додано» / «Змінено» / «Виправлено» українською і
  англійською, з постійним посиланням.
- `CHANGELOG.md` рантайму (`AsteriaCraft/asterium-launcher`, реліз v3.1.1 від 2026-10-01; v3.1.0, v3.0.3, v3.0.2,
  v3.0.1, v3.0.0) - англійською, технічний і довгий (90 КБ): розділи `Performance`, `Added`, `Fixed`,
  `For developers`, `Upgrade notes for LaunchServer admins`, `For players`, `Guards`, `Removed` тощо. Опис релізу
  GitHub - це розділ changelog цієї версії. Майже кожен пункт починається жирним реченням-підсумком
  («**Every main screen is ready before its first visit**»).
- У престартера changelog немає зовсім.
- Релізи обох репозиторіїв мають підписаний `release.json`; актив, перелічений у ньому, автентичний.

## Рішення

1. **Джерело правди - актив `release-notes.json`** у кожному релізі (престартер з 0.3.0; рантайм - з наступного
   релізу, якщо власник погодиться), перелічений у `release.json`, отже підписаний:

   ```json
   {
     "schema": 1,
     "component": "prestarter",
     "version": "0.3.0",
     "date": "2026-10-15",
     "notes": {
       "uk": { "added": ["…"], "changed": ["…"], "fixed": ["…"] },
       "en": { "added": ["…"], "changed": ["…"], "fixed": ["…"] }
     }
   }
   ```

   Пункти - для гравців: одне речення до 300 символів, до 20 у розділі, без внутрішніх деталей. У репозиторії файл
   лежить як `release-notes/<версія>.json`; CI перевіряє схему, що `version` і `date` збігаються з версією і датою
   заголовка `CHANGELOG.md`, і що є обидві мови.
2. **Запасний шлях для релізів без файла** (рантайм ≤ 3.1.1): API бере опис релізу GitHub і розбирає Markdown:
   `### Added` → added, `### Fixed` → fixed, `### Changed`, `### Performance`, `### For players`, `### Removed` →
   changed; `For developers`, `Upgrade notes…`, `Guards`, `Security`, `Known limitations` пропускаються. З кожного
   пункту верхнього рівня береться жирне речення, інакше перше речення, обрізане до 300 символів. Мова - en
   (`notesLocale: "en"`), сайт показує мітку «англійською».
3. **Фікстури сайту** містять написані вручну українські й англійські нотатки для рантайму 3.0.0-3.1.1 (за
   справжнім `CHANGELOG.md`) і для престартера 0.2.0, з реальними датами релізів GitHub (v3.1.1 2026-10-01,
   v3.1.0 2026-10-01, v3.0.3 2026-09-30, v3.0.2 2026-09-30, v3.0.1 2026-09-30, v3.0.0 2026-09-29; престартер v0.2.0
   2026-09-29).
4. Лише стабільні релізи (`channel: stable`); дата - `date` з нотаток, інакше `publishedAt` релізу.

## Наслідки

- Автор релізу пише кілька речень для гравців двома мовами в тому самому PR, що й changelog. CI не пропустить реліз
  без них (для престартера одразу; для рантайму - коли власник погодиться).
- Технічний changelog лишається для розробників і адмінів LaunchServer; на сайт він потрапляє лише як запасний шлях.

## Перевірка

- Лейн prestarter: перевірка `release-notes/<версія>.json` у `ci.yml` і `publish.yml`, актив у релізі.
- Лейн site: схема і фікстури; документ для API описує обидва шляхи; тест розбору Markdown на справжніх описах
  релізів v3.0.0-v3.1.1 (зафіксованих як фікстури) - кількість пунктів у кожному розділі.
