# ADR 0008. Тестові перевизначення лише на loopback, у тому самому бінарнику, що отримує гравець

- Статус: запропоновано (етап Design, 2026-10-02)
- Пов'язані: [0006](0006-launching-the-launcher.md), [0009](0009-ci-matrix-release-assets-and-manifest.md)

## Контекст

Smoke-тести мають проганяти саме ті байти, що підуть у реліз, і не чіпати продакшн: справжній `Asterium.jar` з
`launcher.asterium.pro` відкрив би з'єднання з продакшн-LaunchServer. Окрема «тестова» збірка (cargo feature)
означала б, що перевірено не те, що випущено, і подвоїла б час збирання на семи цілях.

## Рішення

Релізний бінарник читає рівно чотири змінні середовища (модуль `net::overrides`, одне місце з тестами):

| Змінна | Що робить | Обмеження |
|---|---|---|
| `ASTERIUM_PRESTARTER_JRE_API` | базова адреса API Liberica | лише `http(s)://127.0.0.1:<порт>/…` або `http(s)://[::1]:<порт>/…` |
| `ASTERIUM_PRESTARTER_LAUNCHER_URL` | адреса jar для режиму копії | те саме |
| `ASTERIUM_PRESTARTER_STORE` | каталог сховища замість типового | абсолютний шлях |
| `ASTERIUM_PRESTARTER_NONINTERACTIVE` | `1`: повідомлення ОС пишуться в журнал замість вікон | нічого не перенаправляє |

- Ім'я `localhost` не приймається (його розв'язання залежить від `hosts`), лише літеральні адреси loopback.
- Значення, що не проходить обмеження, - помилка з поясненням (код виходу ненульовий), а не мовчазне повернення
  до типової адреси: тест не може «пройти» проти продакшну.
- Будь-яке перевизначення пишеться в журнал як `WARN override …`, а вікно показує мітку «тестовий режим».
- Інших перемикачів немає; README перелічує ці чотири.

## Чому це безпечно

Задати змінні середовища процесу може лише той, хто вже виконує код від імені гравця: він і так може підмінити
будь-який файл гравця. Обмеження loopback не дає перевизначенню перетворитися на канал доставки з мережі
(наприклад, через ярлик з чужою адресою): на loopback слухає лише код, що вже працює на цьому комп'ютері.

## Наслідки

- CI і e2e LaunchServer (gravit-docker) запускають релізні бінарники проти локальних серверів: мок API Liberica або
  справжній API, локальний `Hello.jar` або jar з тестового LaunchServer.
- Підтримка може попросити гравця запустити престартер з `ASTERIUM_PRESTARTER_STORE` у чистий каталог для
  діагностики, нічого не видаляючи.

## Перевірка

Модульні тести `net::overrides`: приймаються `127.0.0.1` і `[::1]` з портом; відкидаються `localhost`,
`127.0.0.1.nip.io`, `10.0.0.1`, `http://user@127.0.0.1@evil`, порожній порт, відносний шлях сховища; мітка і запис
у журналі з'являються.
